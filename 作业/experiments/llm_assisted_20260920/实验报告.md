# 任务三：LLM 辅助轨迹清洗实验报告

实验日期：2026-09-20  
实验目录：`experiments/llm_assisted_20260920`  
数据：`traj_dict.json`，11,386 辆车  
执行环境：本机 Python 3.12；未设置 `DSH_TRAJ_LLM_API_KEY`，模型提供者为 `MockProvider`

## 1. 实验目的

本次实验按助教提供的 `traj_agent` 框架运行，验证“诊断卡 → 参数提议 → 确定性核验 → 记忆准入”的闭环，并比较以下四种模式：

| 模式 | 提议来源 | 记忆 | 确定性搜索 |
| --- | --- | --- | --- |
| `llm-only` | MockProvider | 无 | 无 |
| `search-only` | 关闭模型 | 无 | 有 |
| `llm+search` | MockProvider | 无 | 有 |
| `llm+memory+search` | MockProvider | 有 | 有 |

本次结果用于验证代码流程和评价方法。由于 MockProvider 是脚本化模拟器，不能把结果解释成真实 LLM 的能力。

## 2. 可复现性与正确性检查

- 完整测试：`293 passed in 177.61s`。
- 端到端实验耗时：196.47 s。
- 所有新输出均写入本实验目录，没有覆盖原始 `demo_out`。
- 示范集和留出集各 12 条轨迹，二者无重叠。
- 留出集覆盖六种 `(regime, timeline_quality)` 组合，每种两条：静止/混合/运动 × 正常/退化时间轴。
- 评测阶段的记忆为只读，并排除当前轨迹，避免把留出样本的结果写回记忆。

## 3. 数据抽样检查

原演示脚本把按 ID 排序后的前 200 辆称为“分层抽样”，实际结果为静止 147、混合 31、运动 22；这种选法可能受车辆 ID 排列影响。

本次额外使用固定随机种子 `20260920` 抽取 200 辆：

| 类型 | 数量 | 比例 |
| --- | ---: | ---: |
| 静止 | 94 | 47.0% |
| 混合 | 48 | 24.0% |
| 运动 | 58 | 29.0% |
| 正常时间轴 | 173 | 86.5% |
| 退化时间轴 | 27 | 13.5% |

这个差异表明，排序取前 200 辆不适合估计总体类型分布。固定随机样本也只有 200 条，因此本报告不把 47.0% 写成全量数据集的精确静止比例。抽样 ID 保存在 `output/random_sample_200.json`。

## 4. 单轨迹闭环结果

车辆 246 被诊断为 `moving / ok`。MockProvider 提议：

```json
{
  "dist_threshold": 400.0,
  "dp_tolerance": 15.25,
  "dt_threshold": 30.0,
  "max_speed_mps": 38.0
}
```

执行结果：106 个去噪后点被简化为 19 个，压缩率 82.08%，最大几何偏差 11.91 m；轨迹长度由 11,322.09 m 变为 11,290.64 m。提议得分 0.600534，默认基线 0.632560，搜索最优 0.636188，绝对 regret 为 0.0357，超过 0.01 的小提升空间阈值，因此没有写入记忆。

该案例说明核验器会拒绝“压缩率较高但综合得分低于基线”的提议，闭环门控正常工作。

## 5. 留出集消融结果

### 5.1 全部 12 条留出轨迹

静止轨迹的目标函数被标记为不适用，得分按 0 计。为与助教输出保持一致，先列出全体汇总：

| 模式 | 平均得分 | 相对默认基线平均变化 | 优于基线比例 | 平均 LLM 工具调用 |
| --- | ---: | ---: | ---: | ---: |
| `llm-only` | 0.3072 | +0.0026 | 50.0% | 3.0 |
| `search-only` | 0.3043 | -0.0004 | 16.7% | 0.0 |
| `llm+search` | 0.3070 | +0.0025 | 50.0% | 3.0 |
| `llm+memory+search` | 0.3071 | +0.0025 | 50.0% | 3.0 |

`regret` 在关闭搜索与开启搜索时口径不同，因此没有用跨模式平均 regret 排名。助教原始 `report_ablation.png` 仍展示平均 regret，只适合查看同口径模式；本次另生成 `report_comparable_metrics.png`，统一使用相对默认基线的绝对得分变化。

### 5.2 仅看目标函数适用的 8 条轨迹

| 模式 | 平均得分 | 相对默认基线平均变化 | 优于基线 | 95% bootstrap 区间（平均变化） |
| --- | ---: | ---: | ---: | ---: |
| `llm-only` | 0.460842 | +0.003879 | 6/8 | [-0.000331, 0.008021] |
| `search-only` | 0.456379 | -0.000625 | 2/8 | [-0.001446, -0.000030] |
| `llm+search` | 0.460556 | +0.003782 | 6/8 | [-0.000115, 0.007680] |
| `llm+memory+search` | 0.460699 | +0.003774 | 6/8 | [-0.000358, 0.007928] |

区间用固定随机种子 `20260920` 对 8 个适用样本进行 20,000 次非参数 bootstrap。样本很少，三个含 Mock 的模式区间均覆盖 0，不能据此声称稳定优于默认参数。

### 5.3 记忆贡献的配对比较

在相同的 8 条适用轨迹上，`llm+memory+search` 相对 `llm+search` 的平均得分变化为 **+0.000143**，6 条略升、2 条略降；95% bootstrap 区间为 **[-0.000087, 0.000376]**。变化量很小且区间覆盖 0，本次实验没有测出明确的记忆收益。

示范阶段共写入 12 个情景案例，其中 5 个通过准入；已准入案例为 4 条静止轨迹和 1 条混合轨迹，没有运动轨迹。这种记忆内容分布也不足以支持“记忆能稳定改善运动轨迹参数”的结论。

## 6. 能得出的结论

1. 助教框架在当前环境可完整运行，测试、诊断、工具调用、确定性搜索、regret 核验、只读留出评测和记忆门控均能执行。
2. 核验器能拒绝车辆 246 上明显低于基线的高压缩提议，说明“模型提议”和“代码判分”确实分离。
3. 在 12 条平衡留出轨迹上，Mock 提议相对默认基线的平均改善很小；只看 8 条适用轨迹，置信区间仍覆盖 0。
4. 加入当前记忆后的配对增益接近 0，没有观察到明确记忆效果。
5. 排序取前 200 辆会明显改变类型比例；数据集分布统计应改为固定种子随机抽样或分层抽样。

## 7. 当前不能得出的结论

- 不能证明真实 LLM 比默认参数或确定性搜索更好，因为本轮没有真实模型凭据。
- 不能证明记忆机制有效；当前示范案例少，而且准入记忆偏向静止轨迹。
- 不能把内部目标函数得分视为道路真实质量；当前没有真实路网匹配、人工漂移标注或外部真值。
- 不能把平衡留出集的平均分当作全量 11,386 辆车的总体加权表现。

## 8. 下一轮真实模型实验设计

取得 ECNU 或其他 OpenAI 兼容端点的凭据后，应保持本轮 12 条留出轨迹、默认参数、搜索预算和随机种子不变，只替换 provider。建议至少重复三次真实模型调用，并记录：JSON 成功率、参数越界率、得分相对基线变化、同预算 search-only 对照、token、延迟和失败重试。真实模型结果应另存新目录，不覆盖本次 Mock 结果。
