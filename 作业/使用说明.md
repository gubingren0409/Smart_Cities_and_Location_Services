# LLM 辅助轨迹清洗评估 · 使用说明

本文档说明怎么用这套工作流：**让 LLM 选评估工具、提参数建议，再用定量指标核验建议**。

---

## 1. 它做什么

给一条车辆轨迹，自动完成：

1. 生成诊断卡（类型、时间轴质量、异常计数，不含坐标）
2. 检索历史经验（相似案例的参数区间 + 人类知识笔记）
3. **LLM 决定**：调哪些工具、提什么参数、预期效果是什么
4. **确定性代码判分**：从默认参数独立搜索内部参考，再计算 LLM 候选的 regret
5. 所有案例进入 L1 留档；只有通过核验的案例可被检索并进入 L2

关键点：**LLM 只负责提建议，不负责算数，也不负责判断自己对不对。**


**不要把这些写进任何提交到仓库的文件里。**

验证配置是否生效：

```bash

```

看到 `"would_use": "OpenAICompatProvider"` 就说明会走真实模型。
如果没配 key，会自动回退到离线 Mock，流程照样能跑通（用于无网络演示与测试）。

### 2.3 省 token 的关键设置（重要）

实测数据（车辆 246，ecnu-plus）：

| 配置 | prompt tokens | LLM 轮次 | 结果 |
|---|---|---|---|
| 全工具 + 强制调用 + 8 轮 | 25116 | 6 | 拿不到有效提议，回退默认值 |
| 精简工具 + 自动调用 + **无工具直答** | **2860** | **1** | 成功，来源 `llm-direct` |

**省了 89% 的 token。** 三个关键点：

1. **先让模型直答，不要一上来就给工具。** 决策所需的诊断信息已经全在
   系统提示里，工具并非必需。代码默认 `direct_first=True`，
   直答拿不到 JSON 才升级到带工具的路径。
2. **工具 schema 每轮都要重发，是最大的开销来源。** 默认只发 3 个
   （`suggest_param_range` / `run_search` / `detect_anomalies`），
   并且给过两次工具机会后就撤掉，逼模型给最终答案。
3. **思考模式显式关闭。** 代码默认传 `thinking: {"type": "disabled"}`。

千万不要设 `tool_choice="required"`：那样模型每轮都被强制调工具，
永远没机会输出最终 JSON。实测就是这样浪费了 15000 tokens。

### 2.4 ECNU 平台的注意事项

| 项目 | 值 | 说明 |
|---|---|---|
| BaseURL | `https://chat.ecnu.edu.cn/open/api/v1` | OpenAI 兼容 |
| 推荐模型 | `ecnu-plus` | Qwen3.8-27B，支持 Tool Calls 与结构化输出 |
| 旗舰模型 | `ecnu-max` | DeepSeek-V4-Flash，更长上下文，成本更高 |
| 并发上限 | 每模型 3 | 超限直接返回 HTTP 429 |
| 单轮延迟 | 实测 0.4–85 秒，波动很大 | 首轮常需 60–85 秒，要有耐心 |
| 计费 | 峰谷计价 | 周一至周五 8:00-23:00 为峰时，credits 翻倍 |

**因为并发上限是 3，不要并行跑多个 agent。** 顺序执行即可。

## 3. 最小用法

### 3.1 跑一条轨迹

```python
import sys, json
sys.path.insert(0, '.')

from traj_agent.core import traj as tm
from traj_agent.agent.loop import TrajCleaningAgent
from traj_agent.agent import provider as prov
from traj_agent.memory.store import MemoryStore

raw = tm.load_raw("traj_dict.json")
mem = MemoryStore("memory.sqlite")
agent = TrajCleaningAgent(llm=prov.build_provider(), memory=mem).attach_dataset(raw)

result = agent.run("246")

print("LLM 提的参数：", result.proposal_params)
print("它的依据：", result.proposal_raw.get("rationale"))
print("regret：", result.verification["regret"])
print("是否准入记忆：", result.verification["admitted"])
```

### 3.2 结果里有什么

| 字段 | 含义 |
|---|---|
| `proposal_params` | LLM 提出的清洗参数 |
| `proposal_raw.rationale` | LLM 给出的理由 |
| `proposal_raw.expected_effect` | LLM 预测的各参数升降方向 |
| `verification.regret` | 相对确定性搜索最优的差距（**核心判据**） |
| `verification.direction_accuracy` | 方向预测与实测符号的一致率 |
| `verification.admitted` | 是否通过核验、允许写入记忆 |
| `measured` | 实测指标（压缩率、偏差、Hausdorff） |
| `trace` | 每一步做了什么（可打印出来给学生看） |
| `token_usage` | token 消耗 |

### 3.3 打印完整过程

```python
for s in result.trace:
    print(f"[{s.index:2d}] {s.kind:6s} {s.name:24s} "
          f"{json.dumps(s.detail, ensure_ascii=False)[:90]}")
```

`kind` 取值：`tool`（工具调用）、`llm`（模型回合）、`verify`（核验）、`memory`（记忆）。

## 5. 代码结构

```
traj_agent/
├── core/       确定性算法，零 LLM 依赖，可单测
│   ├── geo.py          坐标与距离（局部等距投影）
│   ├── segment.py      按时间/空间阈值切分
│   ├── anomalies.py    异常点规则 + 原因字段
│   ├── clean.py        去噪（保留原因账本）
│   ├── simplify.py     Douglas-Peucker
│   ├── metrics.py      点数/长度/Hausdorff/Fréchet/耗时
│   ├── diagnosis.py    诊断卡（喂给 LLM 的唯一视图）
│   └── params.py       参数物理先验
├── road/       路网匹配协议（接口就位，可选依赖）
├── tools/      15 个 JSON-Schema 工具（LLM 唯一能接触的层）
├── verifier/   目标函数 · 搜索 · regret 核验 · 消融
├── memory/     SQLite 四层记忆 + 12 维特征 kNN + 导出
├── agent/      ReAct 主循环 + provider
└── report/     六类报告图
```

**依赖是单向的**：`core` 不知道上面任何一层的存在。由 `tests/test_architecture.py` 强制检查。

## 6. 工具清单（LLM 能调用的全部）

| 类别 | 工具 | 作用 |
|---|---|---|
| 查数据 | `load_trajectory` `profile_trajectory` `detect_anomalies` `evaluate` `compare_handles` `suggest_param_range` | 返回标量统计 |
| 改数据 | `split_trajectory` `clean_trajectory` `simplify_trajectory` `apply_road_constraint` | 产生新句柄 |
| 做实验 | `run_search` `find_knee` | 扫参数、取拐点 |
| 查经验 | `query_memory` `query_playbook` | 相似案例 + 人类笔记 |
| 出图 | `render` | 叠加图 / 异常分布 / 热力图 |
| **刻意不给** | `write_memory` `write_playbook` | **LLM 无权写记忆** |

最后一行是设计，不是遗漏。有测试专门断言工具名里不含 `write`/`save`/`delete`。

## 7. 参数怎么调

### 候选与内部参考两条路径

| 段 | 做什么 | 谁做 |
|---|---|---|
| ① 物理先验定区间 | 9 个参数各有合法区间与依据 | 确定性代码 |
| ② 独立提出候选与方向 | 强制结构化输出，含预期效果 | LLM |
| ③ 独立建立内部参考 | 从默认参数开始坐标下降；不以 LLM 候选为起点 | 确定性代码 |

### 参数区间

| 参数 | 区间 | 依据 |
|---|---|---|
| `dp_tolerance` | [0.5, 30] 米 | 上限约等于 GPS 定位精度 CEP（8 米），超过它就在删真实几何 |
| `dt_threshold` | [15, 180] 秒 | 下界保住正常的 20 秒采样，上界对应真实停车 |
| `dist_threshold` | [50, 3000] 米 | 由 Δt × 限速 × 安全系数推导 |
| `max_speed_mps` | [15, 55] m/s | 下界不低于城区限速，上界覆盖噪声下的高速 |
| `max_turn_deg` | [45, 175] 度 | 上界保留极限掉头 |

### regret 的三种口径

**必须按口径读，不能混用：**

| 口径 | 触发条件 | 含义 |
|---|---|---|
| `normalized` | 最优与基线差距充足 | 丢掉了多少比例的可得收益 |
| `absolute(small_headroom)` | 差距 < 0.02 | 退回绝对口径，阈值 0.01 |
| `not_applicable` | 轨迹短于 200 米 | 压缩率无物理含义，改按类型正确性准入 |

混用的后果：headroom 只有 0.021 时，一个与基线持平的提议会被算成 regret 1.0。

## 8. 四层记忆

| 层 | 存什么 | 谁写 | 怎么用 |
|---|---|---|---|
| 工作记忆 | 当前轨迹诊断卡与已试参数 | agent | 单条内 |
| 情景记忆 | 全量（诊断 → 参数 → 指标） | **核验器** | 积累经验 |
| 程序记忆 | 诊断签名 → 参数区间 | **核验器** | 12 维特征 kNN |
| 人类知识 | 结论 + 证据 + 反例 | **人** | 只读 |

情景记忆 L1 会记录 admitted=False 的失败案例，用于复盘和统计；默认相似
案例检索只使用 admitted=1，程序记忆 L2 也只从已准入案例蒸馏。失败案例
因此会被留档，但不会成为后续参数推荐。


## 10. 常见问题

**Q：没有 API key 能跑吗？**
能。会自动回退到离线 Mock provider，全流程可跑通，用于测试与无网络演示。
但 Mock 每次给出同一个拐点，消融表没有信息量。

**Q：报 HTTP 429？**
ECNU 每模型并发上限 3。不要并行跑 agent，顺序执行。

**Q：regret 一直是 1.0？**
检查基线口径。如果基线被设成搜索起点，headroom 会趋零。代码已修，若复现请查 `verifier/verify.py` 的 `compute_regret`。

**Q：LLM 不给有效 JSON 怎么办？**
`proposals.proposal_from_text` 会依次尝试代码块、全文、平衡花括号片段。
全部失败时回退到物理先验默认值，并在 `proposal_source` 标注为 `fallback`。

**Q：想换模型？**
改 `DSH_TRAJ_LLM_MODEL` 即可。任何 OpenAI 兼容端点都能用，代码不用改。
不支持 function-calling 的模型会走文本 ReAct 协议。

**Q：单个用户的配额在哪看？**
https://developer.ecnu.edu.cn/vitepress/llm/limit.html
