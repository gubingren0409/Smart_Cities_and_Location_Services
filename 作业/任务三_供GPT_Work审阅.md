## 0. 课程原始要求与作业包来源

根目录的实验课1.pptx是课程要求的第一手材料：第17–22页依次介绍GPS中断对应分段、GPS漂移对应去噪、冗余点对应Douglas–Peucker简化；第24–25页用骑行场景的12秒采样、25km/h速度上限推导约83m最大位移，示例距离阈值为95m。这个95m是PPT中的骑行例子，不应直接作为所有车辆轨迹的统一阈值。第26页将三步预处理、评价指标与实验报告列为必做，将“基于助教开发的系统”的LLM辅助质量提升及思考讨论列为选做。第28–40页说明任务三的四步工作流、15个注册工具、四层记忆、消融方式及未验证事项；第42页提出三步预处理能否调换顺序的问题。

根目录作业.zip已经包含 traj_agent、任务三notebook、README、使用说明、决策记录、消融报告、测试、图表与原始数据，说明本项目提供的任务三框架并非只有接口空壳。逐文件对比，当前目录的 traj_agent 全部Python源码及上述说明文档与压缩包中的对应文件字节一致；两份notebook与压缩包版本不同。原始作业一notebook有19个单元，其中分段、去噪、简化三个函数是待填空；原始任务三notebook有33个单元且未执行。当前目录的两份notebook已经过后续填写、展示修正和执行，审阅时应与压缩包原版区分。

## 1. 目标与现状

课程的选做任务是“基于 LLM 辅助的轨迹数据质量提升智能体系统”。现有实现让模型根据不含坐标的诊断卡提出参数及预期效果；确定性代码执行清洗、搜索候选参数、计算目标分数和 regret，再决定是否允许建议进入记忆。系统已经有可运行的离线 MockProvider、OpenAI 兼容模型适配器、四种消融模式和报告图。当前证据主要证明流程能运行，尚不能证明真实 LLM 或记忆能稳定提升轨迹质量。

原始数据为 traj_dict.json，约 44.8 MB，包含 11,386 辆车的时间戳与经纬度轨迹。任务三代码可加载全量数据，但现有智能体评测只覆盖小样本；没有人工标注的真实轨迹、漂移点或完整路网真值。不要把数据集大小误写成智能体已全量验证的规模。

## 3. 代码机制

1. core/diagnosis.py 从轨迹生成 regime、时间轴质量、采样、速度、异常等标量诊断；模型提示词使用诊断卡和句柄，源码设计不向模型发送整条坐标。
2. tools/registry.py 注册15个确定性工具；agent/loop.py 默认只把 suggest_param_range、run_search、detect_anomalies 三个工具的 schema 放进模型工具集，且先尝试无工具直答。演示稿中的“15个工具”指工具层总量，并非默认每轮都提供给模型。
3. agent/provider.py 有离线 MockProvider 与 OpenAI 兼容适配器；没有 API key 时回退 Mock。当前 notebook 显示 has_api_key=False、would_use=MockProvider。
4. verifier/search.py 在物理参数范围内搜索；verifier/objective.py 用压缩率、相对参考轨迹的几何保真度、可选路网项与运行时间组成内部目标；verifier/verify.py 计算约束、方向准确率和 regret。
5. memory/store.py 与 memory/retrieve.py 保存已核验案例、提炼参数区间并检索相似诊断。留出集评测只读，检索排除当前样本；模型没有直接写记忆的工具。
6. road/matcher.py 提供路网接口及离线实现；默认没有真实路网，road_match_rate 可为空。因此目前评分主要是内部代理指标，不是道路真实质量分。

## 4. 已有结果，应分开引用

- notebook 的演示：4辆指定车辆，四种模式各4条；离线 Mock。输出中 search-only 的平均分为0.5826，三个含 Mock 模式约0.57。这个演示不使用报告中的12条留出集方案，不能与报告表合并成一个样本。
- 消融报告：12条示范轨迹积累记忆，12条互不重叠的留出轨迹评测；离线 Mock。记忆模式与无记忆模式的平均提议分均约0.3075，相对基线提升均约0.0025，未观察到记忆收益。已准入记忆主要来自静止轨迹，行驶类缺少已验证案例。
- ECNU 历史调用记录：报告载有两辆车的真实模型输出及 token 记录。车辆246的一次提议 regret 0.0233、未准入；车辆0作为短静止轨迹标记为目标函数不适用，按类型正确性准入。记录规模不足以说明真实模型总体效果，也不是四模式真实模型消融。
- 演示报告中的跨模式 regret 有不同口径：关闭搜索时为绝对口径，含搜索时可为归一化口径。应优先比较同口径的相对基线提升、超基线率，或在统一评估预算下重算。

## 5. 审阅时必须核对的差异

1. DECISIONS.md 与示例知识笔记称车辆352的170点“全部落在3秒内、仅4个不同时间戳”。当前 traj_dict.json 中车辆352有170点、54个不同时间戳，首末时间跨度543秒。notebook 的诊断输出也显示时间间隔中位10秒、P95为20秒、零间隔比例约68.6%。旧描述不可直接进入最终报告。
2. README/DECISIONS 中“约63%静止”的统计与 demo_out/summary.json 所列200条样本的147条静止（73.5%）不同。可能来自不同抽样方式；应写清样本、抽样规则与版本，避免说成全量比例。
3. notebook 的4辆车消融与 ABLATION_REPORT 的12条留出集消融使用不同流程、阈值和样本。不要引用某个表的分数解释另一个表。
4. 目标函数的最优解由同一套内部指标和确定性搜索定义。regret 能评价模型是否接近“内部目标最优”，尚不能独立证明真实轨迹清洗更好。实际路网未接入，缺少人工标注或外部真值。
5. README 与 PPT 的部分叙述仍偏方案说明，如“记忆能让流程越跑越省”；现有消融没有测出记忆增益。对外结论应以实测结果而非设计意图为准。
6. 任务三 notebook 的4辆车消融表把 total tool_calls 标作“平均调用”，所以 search-only 显示1.0；12条留出集报告统计的是 llm_tool_calls，search-only 为0。应把表头写清为“总工具调用”或“LLM工具调用”，不能混读。

## 6. 建议请 GPT Work 审阅的方案

第一步，做证据审计：给每个核心主张标明来源文件、样本量、Mock/真实模型、评估口径、是否能从当前数据重跑。先修正车辆352和静止占比等明显过期描述。

第二步，评审指标：检查目标函数权重、短轨迹不适用规则、regret 三种口径及准入阈值。明确“内部搜索最优”与“真实清洗质量”的区别，提出少量独立指标或人工标注方案。

第三步，评审消融：统一示范集与留出集，按 regime 和时间轴质量分层，报告每类样本数、置信区间或重复抽样波动；坚持无记忆/无搜索/无模型模式在结构上真正不同。优先补足行驶类记忆后再测记忆贡献。

第四步，评审真实模型实验：以同一批留出轨迹和调用预算比较 Mock、真实模型与 search-only；记录失败率、实际 token、延迟、成本、参数约束违规和相对基线收益。真实模型实验需使用用户自己的凭据，当前材料不包含凭据。
